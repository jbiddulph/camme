Exhibitionist.me (Camme) — User Guide

This guide explains how to use the Camme web app (branded as Exhibitionist.me) as a viewer or broadcaster, including how Lovense interactive toys work when tips are sent.

1. Getting started

1.1 What you need

  • A modern browser (Safari or Chrome on desktop and iPad).
  • A stable internet connection.
  • For live video: allow camera and microphone when prompted (broadcasters only).

1.2 Open the site

Visit your Exhibitionist.me URL (local development is often http://localhost:8080). The logo in the top-left links home.

1.3 Create an account or sign in

  • Go to Login / Sign up.
  • Use the tabs: Login first, then Sign up if needed.
  • After login, your session is stored in the browser (token used for API calls).

2. Home page

  • Live broadcasters — choose Watch live to join as a viewer.
  • Broadcast Public / Private — signed-in hosts start a stream and go to the live room.
  • Camera test (/cam-test) — test camera/mic without LiveKit if video fails.

Signed-in users may be redirected to /live for the studio flow.

3. Profile, tokens, and payouts

3.1 Profile

Menu → Profile & payouts (/profile): display name, payout-related fields, ID verification status (as configured by the operator).

3.2 Tipping wallet vs broadcaster earnings

  • Tokens — bought on Buy tokens (/buy-tokens, Stripe) or starter balance; spent when you tip a host.
  • £ earnings — hosts accrue value when tipped (typically about £0.05 per tipped token). Details: Tips & earnings (/tips).

The top bar about “tokens to spend tipping” is mainly for viewers. It may be hidden while you are broadcasting.

3.3 Payouts (overview)

  • Minimum payout threshold (often £50) and pay periods depend on operator settings.
  • Identity verification and complete payment details are required before payouts.

4. Watching a live stream

  • From home, Watch live, or use a private watch link.
  • Chat: signed-in users use their username; guests appear as Viewer1, Viewer2, etc.
  • Tips: signed-in viewers use the tip panel; tokens are deducted from your wallet; the host may receive Lovense vibration if they use compatible toys (see Section 8).

5. Broadcasting

  1. Step 1 — Browser test on the live page: confirm camera/mic preview works.
  2. Wait until status shows Connected.
  3. Step 2 — Go live (LiveKit) to publish video and audio.
  4. Use mute/camera controls or Leave to exit; hosts may save or delete room chat afterward.

On iPad, if Step 2 times out, close other apps using the camera and retry Step 1.

6. Menu reference

  • Home, Login / Sign up, Profile & payouts, Buy tokens, Tips & earnings, Camera test, Log out.

7. Privacy and support

  • Log out on shared devices. Report abuse via in-product reporting where available.
  • Payment or verification issues: contact Exhibitionist.me operator support.

8. Lovense interactive toys — how it works

Exhibitionist.me can connect Lovense sex toys to the tipping system so that when viewers tip during a live show, the broadcaster’s toy may vibrate automatically. This uses Lovense’s official Standard / Basic SDK integration — not a separate Lovense login with the same name as your Camme username.

8.1 Who needs what

RoleLovense setup
Viewer (tipper)No Lovense app or account required. Tip with tokens as usual; vibration is handled on the host side.
Broadcaster (model)Compatible Lovense toy + Lovense Connect running on the same computer/browser session used for /live broadcast. Toy must be linked to the site’s Lovense developer integration.
Site operatorLovense Developer account, developer token, and platform (website) name configured on the API server (see Section 9).

8.2 End-to-end flow (what happens when someone tips)

  1. A signed-in viewer sends a tip (token amount) on the live page for that room.
  2. The server records the tip, deducts the viewer’s token_balance, and stores vibration parameters derived from the tip size.
  3. The broadcaster’s browser polls the tip inbox every few seconds while hosting.
  4. When a new tip appears, the page shows a “tip received” banner and calls the Lovense SDK command sendToyCommand with strength and duration.
  5. If Lovense Connect has the toy connected under the correct integration, the toy vibrates for that duration.

Tips do not go through Lovense’s payment system. Money/tokens are handled by Exhibitionist.me (Stripe for purchases; internal token ledger for tips). Lovense is only used for device control.

8.3 How the broadcaster is linked to Lovense

  • When you go live as a host, the site requests a short-lived auth token from Lovense’s API.
  • Lovense identifies you by your Camme user ID (not your display name). Your display name is sent as a label only.
  • The live page loads Lovense’s Basic SDK in the browser and connects using that token and the operator’s platform name (website name from the Lovense developer dashboard).
  • Your toy must be active in Lovense Connect while broadcasting so the SDK can reach it.

You do not need your Camme username to match a Lovense nickname. What matters is: same developer app, same platform name, Connect running, and you logged into Camme as the host on that broadcast.

8.4 Tip amount → vibration (typical behaviour)

The server maps each tip’s token amount to vibration strength and time (seconds). Larger tips generally produce stronger and/or longer vibration, within capped limits. Example logic used by the platform:

  • Strength: roughly 1–20, based on tip size (e.g. about 1 strength per 50 tokens, minimum 1).
  • Duration: roughly 2–120 seconds (e.g. about 1 second per 25 tokens, minimum 2 seconds).

Exact values are set by the running API; hosts see tip totals under Tips & earnings.

8.5 Broadcaster checklist (before going live with Lovense)

  1. Install Lovense Connect on the device you use to broadcast.
  2. Pair your Lovense toy in Connect and confirm it works in the Connect app.
  3. Log in to Exhibitionist.me and open your live broadcast page (host / broadcast link).
  4. Complete camera Step 1 and Step 2 (Go live) as usual.
  5. Leave Connect running in the background; do not let another app steal the Bluetooth/USB connection.
  6. Ask a test viewer (or second account) to send a small tip; you should see the tip banner and feel vibration within a few seconds.

8.6 Viewer checklist (tipping with Lovense-enabled hosts)

  • Sign in and ensure you have enough tokens (Buy tokens if needed).
  • Join the host’s live room as a viewer.
  • Use the Tip panel: quick amounts or custom value → Send tip.
  • No extra Lovense steps are required on your side.

8.7 Troubleshooting Lovense

ProblemWhat to try
No vibration on tipsConfirm Connect is open, toy connected, host is actually broadcasting (not only watching). Retry after reconnecting the toy in Connect.
Tips work but never vibrateOperator may not have Lovense credentials on the API server, or platform name in config does not exactly match the Lovense developer dashboard website name.
SDK / Lovense errors in browser consoleHost must be logged in; API must return sdk_enabled: true from client-config. Check network to api.lovense-api.com.
Intermittent vibrationTip inbox is polled every ~2 seconds in foreground; delays are normal. Background browser tabs poll slower.
Wrong person’s toy reactsEach Camme user ID is separate; only the logged-in host on that broadcast session should have Connect paired for that integration.

8.8 What Lovense features are not in this guide’s product

  • Viewer remote control via Lovense Viewer JS (encrypted “start control” from viewers) — optional AES keys exist on the server for advanced integrations but are not part of the standard live page UI today.
  • Full Lovense Cam Extension / third-party cam site plugins — this site uses the Basic SDK + in-app tips pattern instead.
  • Lovense handling payments — all purchases and tips are on Exhibitionist.me; Lovense does not process your card or tokens.

8.9 Compatible products

Any Lovense device that works with Lovense Connect and your operator’s Lovense developer application should work, subject to Lovense’s own device and firmware support. The site does not maintain a separate hardware list; refer to lovense.com and Lovense developer documentation for current models.

9. For site operators — Lovense credentials (technical)

This section is for whoever deploys the FastAPI API (e.g. Heroku camme-api). Secrets must never be committed to git or shared in user support chats.

9.1 Environment variables

VariableRequiredPurpose
LOVENSE_TOKENYesDeveloper token from developer.lovense.com (server-side only).
LOVENSE_PLATFORMYesWebsite Name exactly as shown in the Lovense developer dashboard.
LOVENSE_AES_KEYOptionalAES key for Viewer JS startControl (advanced).
LOVENSE_AES_IVOptional16-byte IV for same (advanced).

9.2 API endpoints (prefix /api/v1)

  • GET /lovense/client-config — returns whether SDK is enabled and platform name.
  • POST /lovense/auth-token — broadcaster JWT required; returns Lovense authToken for the Basic SDK.
  • POST /lovense/viewer-control-target — optional encrypted target for Viewer JS (advanced).

9.3 Verify configuration

  1. Set vars on the API host and restart the process.
  2. GET /api/v1/lovense/client-config should show "sdk_enabled": true.
  3. Host broadcasts on /live; send a test tip; confirm inbox + vibration.

Related token economy vars: INITIAL_TOKEN_BALANCE, TOKEN_VALUE_GBP, PAYOUT_MINIMUM_GBP. Database: camme_tips stores vibrate_strength and vibrate_seconds per tip.
